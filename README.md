# market-ingest

Сбор публичных рыночных данных с бирж в ClickHouse. Реализует P0.2/P0.3 роадмапа:
каркас коннекторов и публичные WS. Заменяет Coinglass ($299/мес) первоисточником
с лагом <1 с вместо 20 минут.

## Зачем это существует

Нормализация фактора устроена как `перцентиль 365д → z-score 90д`. Перцентиль за
год невозможно посчитать, не имея года истории, а история — единственный ресурс
проекта, который нельзя докупить задним числом. Каждый день без сбора сдвигает
дату первого валидного сигнала на день.

## Устройство

```
src/ingest/
  chsink.py              батчевая запись в ClickHouse с очередью и back-pressure
  health.py              поминутная статистика, детектор разрывов, события связи
  rest.py                общий REST-клиент: бюджет веса, пауза после 429/418
  book.py                локальный стакан и его посекундный агрегат
  exchanges/base.py      общее для всех бирж: WS-цикл, здоровье, строки стакана
  exchanges/binance_um.py коннектор Binance USDⓈ-M
  exchanges/bybit_linear.py коннектор Bybit linear (USDT/USDC перпетуалы и фьючерсы)
  __main__.py            точка входа: один процесс на биржу
schema/                  DDL, идемпотентный
deploy/                  systemd-юнит, деплой, создание пользователя ClickHouse
```

Один процесс на биржу, не на поток и не на всё сразу: падение коннектора Binance
не должно ронять Bybit, и у каждого свой юнит, своя политика рестарта и свой
журнал.

## Битемпоральность

Каждая таблица несёт **два времени**: `event_time` — когда, по словам биржи,
событие произошло, и `ingest_time` — когда мы о нём узнали. Оба входят в
`ORDER BY`, поэтому исправленное или повторно доставленное наблюдение ложится
**новой строкой рядом**, а не поверх старой.

Отсюда движок — обычный `MergeTree`, а **не** `ReplacingMergeTree`: Replacing
схлопывает строки с одинаковым ключом сортировки и уничтожил бы ровно ту историю
ревизий, ради которой всё это делается. Дедупликация настоящих дублей — запросом
(`LIMIT 1 BY`), а не движком.

Практический смысл: в 03:00 прогнозный фандинг на 08:00 был один, в 07:59 —
другой. Бэктест обязан использовать то, что было известно **на тот момент**:

```sql
SELECT symbol, argMax(funding_rate, ingest_time) AS known_then
FROM market.mark_price
WHERE ingest_time <= '2026-09-10 03:00:00'
  AND event_time  <= '2026-09-10 03:00:00'
GROUP BY symbol
```

## Гранулярность

`!markPrice@arr@1s` отдаёт **935 символов каждую секунду** — 65 млн строк в
сутки, порядка 250 ГБ в год только на Binance. Факторам такая точность не нужна:
фандинг рассчитывается раз в 8 часов, перцентиль за 365 дней от секунд не
зависит. Поэтому два уровня:

- `sampled = 0` — полный поток, только для `focus_symbols` (топ-20);
- `sampled = 1` — последнее значение за минуту, для всех остальных.

Колонка `sampled` обязательна: без неё нельзя отличить «данных не было» от
«здесь другое разрешение».

Сделки и ликвидации пишутся без прореживания — они на два порядка дешевле.

## Ловушка эндпоинтов Binance

23.04.2026 Binance разнёс фьючерсный WS на `/public`, `/market`, `/private` и
отключил legacy-путь `/ws/` для всего из `/market`. Старые URL **принимают
соединение и подписку, но не присылают ничего**:

```
wss://fstream.binance.com/ws/btcusdt@aggTrade         тишина навсегда
wss://fstream.binance.com/market/ws/btcusdt@aggTrade  работает
```

Молчащий открытый сокет — самый дорогой вид отказа: он выглядит как «сейчас нет
сделок» и может простоять месяц. Поэтому у каждого потока есть watchdog
(`stall_seconds` в конфиге): тишина дольше ожидаемой считается ошибкой и ведёт к
переподключению, а не к спокойствию.

## Особенности Bybit

- Подписка сообщением, и Bybit нужен собственный JSON-ping раз в 20 с: без
  него соединение рвётся, несмотря на пинги WebSocket.
- С 26.11.2026 не больше 100 подписок на соединение; сборщик не стартует,
  если основных символов или стаканов больше.
- id сделки — UUID (`trade_id`), сквозной нумерации нет, поэтому потерю
  сделок по id не доказать, как у Binance; `agg_id` хранит `seq` Bybit.
- Стакан Bybit сам держит ровно 1000 уровней и удаляет выпавшие за них,
  поэтому глубина доступна только до 1000-го уровня (у BTC около ±0.25 %).
- Ликвидации — все, а не одна в секунду, как у Binance. `side` — сторона
  ордера ликвидации, как у Binance; сторона позиции от Bybit лежит в `extra`.
- Тикер присылает только изменившиеся поля и молчит, пока mark не меняется,
  поэтому строку mark price основных символов раз в секунду пишет таймер из
  накопленного состояния. Если последнее сообщение старше секунды, в `extra`
  лежит его время (`{"ts": …}`); пока сокет лежит или символ молчит дольше
  минуты, строк нет.
- Open interest и mark price неосновных символов — один запрос
  `/v5/market/tickers` в минуту.
- `openInterest` у Bybit — сумма обеих сторон, ровно вдвое больше, чем OI
  у Binance. В `open_interest` пишется односторонний `singleOpenInterest`;
  собственные цифры Bybit лежат в `extra`.

## Контроль качества

Критерий выхода P0 — `stale` < 1% и непрерывный архив без разрывов > 5 мин.
Пустой час в `market.trades` сам по себе неотличим от часа, когда мы были слепы,
поэтому база `ops` пишет, что коннектор **делал**:

- `ops.connection_events` — каждый connect/stall/error/reconnect;
- `ops.stream_health` — поминутно: сообщений, строк, байт, лаг p50/p99/max;
- `ops.sequence_gaps` — доказанные дыры по разрывам `aggTrade` id;
- `ops.v_silent_minutes` — минуты, в которые поток не дал ничего.

## Запуск

```bash
./deploy/deploy.sh
```

```bash
ssh scali sudo systemctl enable --now market-ingest@binance_um
```

`deploy.sh` по умолчанию деплоит на `scali` (другой хост — через `VPS_ALIAS`) и
перезапускает все включённые экземпляры `market-ingest@*`. Новую биржу он сам
не включает.

### Новая биржа

Имя биржи (например, `binance_um`) — это одновременно аргумент `--exchange`,
секция конфига `[binance_um]`, экземпляр юнита `market-ingest@binance_um` и
значение колонки `exchange`. Чтобы добавить биржу:

1. коннектор в `src/ingest/exchanges/`, наследник `Collector` из `base.py`;
2. строка в `EXCHANGES` в `src/ingest/__main__.py`;
3. секция в `/etc/market-ingest/config.toml` (без неё процесс не стартует);
4. `systemctl enable --now market-ingest@<имя>`.

Графики и алармы Netdata от имени биржи не зависят: алармы заводятся на каждую
биржу сами (`foreach`), как только приходят её метрики.

Конфиг — `/etc/market-ingest/config.toml`, пароль ClickHouse — в
`/etc/market-ingest/env` (создаётся `deploy/setup_ch_user.sh`, пользователь
`ingest` имеет только INSERT/SELECT на `market` и `ops`).
