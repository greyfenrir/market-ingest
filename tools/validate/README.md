# Проверка данных по внешним эталонам

## Зачем и когда

Скрипты проверяют, совпадает ли собранное с тем, что видела сама биржа. Запускать после любой правки стакана, агрегатов или коннекторов: медианы около 1.000 значат, что ничего не сломано. Все скрипты читают ClickHouse только на чтение (HTTP через `CH_URL` или команда `--ch-cmd`, для прода — `~/bin/prod-sql`: локальная обёртка, которая отправляет запрос по ssh с ключом, привязанным на сервере к `clickhouse-client` под пользователем только на чтение; пароль не покидает сервер). Архивы скачиваются и разбираются локально, прод не нагружается.

## Что чем проверяется

| Скрипт | Что проверяет | Эталон |
|---|---|---|
| `binance_compare_bookdepth.py` | глубина Binance на ±0.2/1/2 % | архив Binance `bookDepth` |
| `bybit_compare_ob200.py` | глубина Bybit на ±0.2/0.5/1/2 % по альтам | архив Bybit `ob200` |
| `bybit_selfcheck.py` | код стакана Bybit на всех 1000 уровнях, в том числе BTC и ETH | свежий снимок Bybit по второму соединению |
| `bybit_record_ob200.py` | вспомогательный: пишет живой поток `orderbook.200` в формате архива | — |
| `hyperliquid_check_funding.py` | фандинг и `premium` Hyperliquid | `fundingHistory` |
| `hyperliquid_cross_venue.py` | оракул, mark, фандинг Hyperliquid, масштаб `k`-монет | Binance и Bybit из нашей же базы |
| `hyperliquid_check_rows.py` | правила внутри строки, полнота опросов | правила самого Hyperliquid |
| `binance_bybit_check_funding.py` | ставка перед выплатой и расписание фандинга | история выплат бирж |
| `binance_bybit_check_oi.py` | OI: одна сторона, в монетах | история OI раз в 5 минут |

Запуск: `--date YYYY-MM-DD` (или `--hours N`), символы через `--symbols`. Работают на стандартной библиотеке; `bybit_selfcheck` и `bybit_record_ob200` требуют `websockets`.


## Как читать результат

- Отношение «наше / эталон» по полосе и стороне: медиана, p5–p95, доля срезов в пределах 1 % и 5 %. Берутся только строки `state = ok`.
- У Binance две метрики: `qty` (в монетах, основная) и `usd` (в долларах; на 1–2 % расходится на ~0.5–1 % из-за пересчёта по mark, это не ошибка стакана).
- **Прогрев** стакана Binance после старта: глубине на 1–2 % можно доверять при `book_age_s >= 7200` для BTC, `>= 1800` для ETH, для альтов с первой секунды. Более молодые строки BTC и ETH — нижняя оценка.
- `bybit_selfcheck` в норме: все проверки `equal`, ноль `different`, ноль разрывов; иначе код выхода 1.
